Built on the official @wordpress/env

wp-env, without Node.js
on your machine

Wokenv runs the official WordPress development environment from a container. Docker is the only requirement, and wokenv.yml is the only file in your repository.

curl -fsSL https://raw.githubusercontent.com/wokenv/wokenv/main/install.sh | bash

Requires Docker with Compose v2 and Git. Linux, macOS, Windows with WSL 2.

From clone to WordPress in two commands

  1. wokenv initDetects a plugin, a theme or WordPress core and writes wokenv.yml.
  2. wokenv startwp-env builds and starts WordPress, the database and phpMyAdmin. Wokenv adds Mailpit.
  3. Commit one fileYour teammates run wokenv start and get the same environment.
$ cd my-plugin
$ wokenv init
✓ Created wokenv.yml (type: plugin)
$ wokenv start
WordPress development site started at http://localhost:8888
phpMyAdmin started at http://localhost:9000
✓ Mailpit started at http://localhost:8025
$ wokenv wp plugin list
$ wokenv composer install
$ wokenv npm run build

One file. Standard keys.

The wp-env section takes exactly the keys of .wp-env.json: there is no new configuration language to learn, and the wp-env documentation applies as it is.

Already have a .wp-env.json? Keep it. Wokenv reads it and your wokenv.yml shrinks to one line.

No package.json, no .env, no node_modules and nothing to add to .gitignore: everything else lives in ~/.wokenv.

# wokenv.yml
type: plugin
mailpit: true

# Same keys as .wp-env.json
wp-env:
  phpVersion: "8.3"
  phpmyadminPort: 9000
  testsEnvironment: false
  plugins:
    - https://downloads.wordpress.org/plugin/query-monitor.zip
  config:
    WP_DEBUG_DISPLAY: true

Everything a WordPress project needs, in containers

Wokenv adds what is missing around wp-env and leaves wp-env itself untouched.

Zero setup

Docker is the only requirement

Node.js, npm, PHP, Composer and WP-CLI all run in containers. Nothing else to install or keep up to date.

Official

Unpatched wp-env

Wokenv drives wp-env through its public interface only, so every wp-env feature and release works as documented.

Permissions

Files belong to you

wp-env runs as your user, not as root. Files written by WordPress, WP-CLI or Composer keep the right owner.

Email

Mailpit built in

Every message sent with wp_mail() is caught and shown in a web UI. Nothing leaves your machine.

Debugging

Xdebug and SPX on demand

wokenv start --xdebug enables step debugging and coverage, --spx the profiler, exactly as in wp-env.

Tooling

WP-CLI, Composer, PHPUnit, npm

One command each, run from anywhere inside your project: wokenv wp, composer, phpunit, npm.

Projects

Plugins, themes and core

The project type is detected and mounted for you. Add more plugins and themes from zips, GitHub or local paths.

Database

phpMyAdmin included

wp-env's own phpMyAdmin, one line of configuration away. Each project has its own database.

Teams

Centralized and consistent

Wokenv lives in ~/.wokenv. Update it once with wokenv self-update and every project benefits.

Questions

How does it work?

The wokenv command starts a small container with Node.js and wp-env, mounts your project and the Docker socket into it, and runs wp-env there as your own user. wp-env then creates the WordPress containers on your Docker daemon, exactly as it would from your machine.

Is mounting the Docker socket safe?

It gives the Wokenv container control of your Docker daemon, which is equivalent to root on the Docker host. This is the access wp-env needs to manage containers, and the same it has when installed on your machine. As with wp-env itself, only start projects whose configuration you trust: lifecycle scripts can run arbitrary commands.

My project already uses wp-env. Do I have to migrate?

No. Run wokenv init next to your .wp-env.json: Wokenv uses it as it is, and contributors with Node.js can keep running npx wp-env.

Can I run several projects at the same time?

Yes. Every project has its own containers, database and volumes. Give each one its own ports in wokenv.yml.

Does it work with rootless Docker or userns-remap?

No. With those configurations the user inside the containers does not map to your user on the host, and file ownership breaks. wokenv doctor tells you if your setup is affected.

Why "Wokenv"?

Like a wok that blends different ingredients into one dish, Wokenv blends WordPress, Docker and wp-env into one development environment.
